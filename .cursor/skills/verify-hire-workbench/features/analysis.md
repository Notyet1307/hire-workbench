# 分析任务与证据

## Sub-features

- 针对应聘记录发起规则或模型分析。
- 展示排队、执行、成功、失败和重试。
- 查看逐项状态、原文、信息缺口与面试追问。
- 保存当时岗位和简历快照。

## How to get to it (user POV)

在候选人详情点击“关联岗位”，选择“招聘中”的岗位并“确认关联”。选择分析方式后点击“开始分析”。完成后点击右侧“原文证据”，在左侧简历正文中查看高亮。

## Driving it with Playwright

执行 `npm run e2e -- --grep '完整浏览器路径'`。现有用例通过界面触发规则模式，等待 `.assessment` 出现，点击 `.evidence-quote` 后断言 `page.getByTestId('resume-text').locator('mark')` 可见，保存 `02-evidence-analysis.png`。再通过 `/api/workspace` 检查分析存在、保存正文等于输入、覆盖率大于零且保留未知项。

该用例等待完成结果，没有逐一断言短暂的排队与执行状态。不可据此声称浏览器已验证所有任务状态。

`tests/api.test.ts` 验证输入快照与失败重试，`tests/evaluation.test.ts` 验证引文偏移、结构错误、缺标准、虚构证据、HTTP 错误和超时。模型请求使用隔离的假提供商验证协议边界；真实模型连接需要按 `specs/next.md` 单独运行。

## Gotchas

分数与覆盖率是不同指标。信息不足不等于明确不满足。分析任务失败不能用前次成功报告冒充本次结果。没有正文时不得新建成功分析。旧分析必须使用它保存的原文和标准，不能因当前候选人被修改而变化。
