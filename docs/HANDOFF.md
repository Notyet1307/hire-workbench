# 交接说明

## 从这里接手

先阅读根目录 `AGENTS.md`。启动方式见 `README.md`，产品边界见 `PRODUCT.md`，数据关系见 `ARCHITECTURE.md`。

当前交付是 **Hire Workbench 0.1.0 中文 MVP**。它验证岗位标准、简历正文、证据分析、人工复核与面试的工作流。没有把完整 Harly 项目迁入，也没有接入用户的 Mac mini 或 devbox。

本次实际验证的代码提交为 `458c97e6abfa951cd0ee00f2fff92f2853c1ae16`。类型检查、28 项测试、生产构建、2 条浏览器路径及干净源码启动检查均通过。该 SHA 属于原始私有交付历史，不是公开仓库提交。公开版本从清理后的源码建立独立初始提交，不携带旧历史；当前 head 请使用 git rev-parse HEAD。接手时仍应在当前设备重现适用检查。

## 已实现与验收的区别

功能和 API 合同体现在 `src/shared/types.ts` 与服务端实现。实际执行过的命令、成功结果、浏览器证据和环境限制只以 `TEST-REPORT.md` 为准；不要从源码存在或菜单可见推断验收通过。

本地规则模式是无密钥可运行路径。真实模型 API 的地址、密钥、模型 ID 与业务效果需要在用户环境验证。扫描件 OCR、企业权限、外部招聘渠道和完整 Harly 迁移不在本次完成范围。

## 接下来最值得做的工作

首先执行 `specs/next.md` 的真实模型接入验收。它不要求重写产品底座，而是用授权或脱敏的中文样本验证现有接口与证据约束。只有在样本显示具体缺口后，才修改提示词、模型适配或解析能力。

如果模型连通与证据质量满足预期，再做 OCR。随后按实际使用场景补团队权限、部署与恢复。Go 拆分和大规模人才库搜索后置。

## 接手前检查

- 查看是否存在用户自己的 `.env` 和 `data/`，不要覆盖或清空。
- 阅读测试报告中的环境与未验证项，再在当前机器跑一次 `npm run doctor` 和相关检查。
- 有 Git 时记录真实 base/head；源码包尚未初始化 Git 时明确记为不适用。
- 复用 `.cursor/skills/verify-hire-workbench/`。改变路径、选择器或行为时同步更新地图。
- 不把示例数据和规则模式结论带入真实招聘判断。

## 审阅状态如何判断

本交付的独立检查结果以测试报告为准。**独立跨模型审阅默认记为 BLOCKED（未运行或实际模型未确认）**，直到新的审阅证据明确解除。这个状态只描述跨模型检查，不推翻已经实际通过的本地检查，也不能被悄悄改成 PASS。

后续审阅应接收当前 spec、固定 head 或源码摘要、测试证据和已知限制。让审阅者独立重现用户路径，不只阅读上一位 agent 的总结。
