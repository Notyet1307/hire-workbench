## 浏览器验收具体做了什么

第一条路径从空工作区开始：新建岗位；验证权重错误时不能保存；输入简历并保存候选人；关联岗位；执行本地规则分析；点击引用并检查正文高亮；核对服务端保存的正文快照和信息不足项；保存人工复核；安排面试并填写结论；刷新后再次读取记录；检查工作区导出。核心页面未出现 JavaScript pageerror。

第二条路径通过页面文件选择器上传真实合成 TXT 文件，检查解析后的正文已写入服务端；切换至 390 × 844 的手机视口，检查页面没有整体水平溢出。招聘阶段看板与导航允许在各自容器内横向滚动。

PDF 与 DOCX 的真实解析由自动化解析测试覆盖，浏览器上传路径覆盖 TXT。不要把这两项写成三种格式都完成了浏览器上传验收。原文定位和人工复核来自真实页面操作；一些异常边界则来自 API 与单元测试。

此次浏览器为 Chromium `153.0.8010.0`。容器自带浏览器受到本地套接字限制，标准 Playwright 浏览器下载也未成功，因此使用临时安装的 `@sparticuz/chromium` Linux headless shell 执行同一套 Playwright 测试。没有开启 single-process、disable-web-security、allow-running-insecure-content 或 disable-site-isolation-trials 参数。该临时浏览器不属于产品运行依赖，也未打包进源码。

## 28 项测试覆盖的边界

- **工作流与存储：** 岗位权重、应用关联幂等、异步分析、失败重试使用原快照、资料版本、人工复核、面试记录、SQLite 关闭重开、未完成任务恢复、导出不泄漏配置密钥。
- **规则与证据：** 中文及混合文本、原文偏移、unknown、否定语境、未说明经历、Go 与 Google 的边界。规则模式只给部分证据或信息不足，不声称语义判断或排序准确率。
- **模型契约：** 使用 mock HTTP provider，检验 json_object/json_schema、逐字证据、标准完整性、重复标准、虚构引用、额外字段、HTTP 错误、超时和联系字段屏蔽。这些不是实际模型 API 调用。
- **岗位草稿：** 配置缺失、合格结构、非法结构，以及 40+40 权重、超长关键词等无法保存的草稿。生成输出与保存接口使用同一份约束。
- **文件解析：** 实际生成并读取 UTF-8 中文 TXT、含中文段落的 DOCX、带文字层的 PDF；空白 PDF、损坏文件、旧版 DOC、超大文件与空文件均按约定失败或待补文字。

Linux 测试机如缺少系统库，按 Playwright 安装输出处理。当前平台若已提供可信 Chromium，可通过 `E2E_CHROMIUM_EXECUTABLE` 指定二进制，通过 `E2E_CHROMIUM_ARGS` 传入可信 JSON 参数数组；通常无需设置。

已启动产品实例时，在另一个终端执行 `npm run doctor`。验收脚本采用独立临时数据库，不应清空用户的 `data/`；清理规则见项目验证技能。
