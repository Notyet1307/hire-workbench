# 下一项任务：真实模型与中文样本验收

## 目标

在用户提供的 OpenAI 兼容接口上，验证中文简历评价可以稳定返回可定位原文的结果。保留当前产品结构与规则模式，不先增加新的编排平台。

## 输入与约束

- 使用现有环境变量接入地址、密钥和真实模型 ID，凭据不进 Git、日志或证据文件。
- 使用获得授权或脱敏的简历；首次运行以合成样本开始。
- 准备 3 类岗位、30 至 50 份样本，再由招聘者确定最终评价标准。
- 样本覆盖普通 PDF、DOCX、多栏中文简历、缺少证据的简历、扫描件和接口错误。
- 扫描件未接 OCR 时必须明确停在待补充正文，不以空文本继续评分。

## 要验证的行为

| 场景 | 可观察通过条件 |
|---|---|
| 真实模型联通 | 结果记录实际模式和模型，接口失败显示具体任务失败 |
| 结构化评价 | 每项岗位标准有对应评价，不丢失必需项 |
| 原文引用 | 所有引用都能定位到该分析保存的简历快照 |
| 信息缺失 | 材料未提及时标记信息不足，不直接判为不满足 |
| 版本变化 | 修改简历后新分析采用新版本，旧分析仍可还原 |
| 人工复核 | 保存复核说明，保留分析与人工决定各自记录 |
| 失败重试 | 可见失败原因，重试使用原输入快照，成功后结果唯一可定位 |

## 执行顺序

先跑当前本地验收，固定 base。再测试一个真实模型样本，确认调用路径与引用约束。随后扩大到完整样本集，记录事实提取错误、引用错误、人工修改量、耗时和调用成本。给每种错误保留最小脱敏复现材料。

只有发现明确缺陷时才改代码。每次修改需要固定 head 并重新运行相关用户路径。不能为了让样本通过而降低原文引用校验或把未知改为满足。

## 完成条件

提交实际样本统计和失败案例，不预设效果数字。每项通过结论都有证据，未完成项单独列出。独立审阅给出 PASS、FAIL 或 BLOCKED；缺少有效模型凭据时，这项任务保持 BLOCKED，并保留已完成的本地验证结果。

完成后由使用者根据观察结果决定下一项是 OCR、团队权限还是评价规则修正。不要自动扩展成完整招聘 SaaS。
